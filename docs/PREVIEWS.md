# 视频封面取帧

没有可用海报时，从视频真实画面生成设备本地 JPEG 封面。配置同步服务后，远程视频的封面可作为加密图片记录同步；不上传视频文件或设备本地路径。

成功生成的磁盘封面长期保留，不按时间或缓存总容量自动淘汰；重新打开应用仍可使用。文件身份、进度指纹或封面格式变化时按下述规则更新，只有新图通过校验并成功保存后才替换适用的旧图。作品海报同样长期保存，具体规则见[资料与海报缓存](METADATA.md#海报缓存)。

- 有观看记录：先取保存进度；该位置为黑场/白场时仅尝试前后 0.5 秒和 1.5 秒。都不可用则保留已通过新版质量检查的封面，不能拿远处的剧情画面冒充当前进度。
- 未观看：先取视频约 12% 处（上限 180 秒），不合适再尝试 25%、40%、60%。候选和解码时间都有上限。
- 后台取帧前等待 mpv 的 `seeking=no`、时间位置接近目标且连续两次轮询稳定；`seek()` 命令已返回不等于目标帧解码完成。后台封面解码固定使用软件解码，避免设备硬解表面无法读取时产生黑图。
- 仅在可见卡片需要图片时启动独立封面提取；启动、扫描和导入不再预先解码一批视频。滚动期间暂缓请求，播放器打开时暂停后台封面解码。
- 播放中每 10 秒仅保存和同步进度，不截图。暂停、切后台和退出时合并检查点；当前帧已暂停、定位稳定时才取帧，不循环等待网络定位。截图前后核对时间与定位状态，相同帧不重复截取，缩图、质量检查与写盘异步执行。未稳定或质量不合格时保留适用的旧图，下一次可见卡片请求再按保存进度提取。
- 暂停截图只增量同步当前视频的封面、来源与文件关联，不为单张图片扫描整个影视库。播放期间延后全库配置应用，退出后恢复；桌面独立播放器关闭前完成最后一张本地截图写入，不等待网络同步。
- 对缩小后的真实像素检测近全黑、近全白、透明及无细节的纯色输出。保留正常夜景、有画面内容的黑边和静止动画场景。画面品质检查不是主观选图，不保证每个视频都能找到适合的封面。
- 缓存格式版本为 3。版本 2 的图像未经质量检查，升级后不直接显示，等待重新生成；源不可访问或所有候选均为黑白场时会暂时显示文件图标。同版本已验证的旧图可以在更新失败时继续显示，成功写入新图后才替换。独立封面解码不改变播放位置。
- 同一视频与进度指纹失败后，本次运行不因页面重建重复解码；重新启动、进度变化或明确重试时再尝试。这样全黑视频不会形成持续的解码循环。

Infuse 公开说明确认会在缺少嵌入封面时从视频生成缩略图，但没有公布精确取帧时机和质量筛选算法。这里参考其展示方式，使用上述明确的本地策略，并未声称复刻其闭源算法。参考 [Firecore 开发者说明](https://community.firecore.com/t/option-for-basic-file-list-browsing-without-artwork/20457/4) 和 [mpv seeking 属性](https://mpv.io/manual/master/#properties-seeking)。

## 播放中拖动预览

进度条使用独立的静音软件解码器。拖动事件只替换下一次取帧目标，当前解码完成后立即显示；继续拖动时保留最近成功的帧，随后追上最新目标，主播放器在松手前不定位。每半秒位置复用已生成帧，最多保留一个待处理目标。

单次取帧有 8 秒期限，失败或来源不支持时显示「预览暂不可用」，保留目标时间，不无限转圈。同一拖动内失败后短暂退避；下一次拖动可重试。取消时先关闭来源桥接以解除远程读取等待，再串行释放解码器；旧拖动的迟到结果不进入新拖动。

拖动预览使用的是临时内存帧和活动解码器，仍按空闲、退出及取消时机释放，不写成永久的逐时间点截图。长期保存适用于已落盘的封面、海报和资料缓存，不改变播放器的内存与连接生命周期。

## 回归验证

```sh
python3 scripts/generate_preview_fixture.py
cd client
flutter test test/preview_quality_test.dart test/media_previews_test.dart
xvfb-run -a flutter test integration_test/preview_quality_test.dart -d linux
```

使用真实 H.264 和 HEVC 10-bit MKV、长 GOP、B 帧，画面包含黑头、白头、时间戳测试图及中途黑场。验证默认候选跳过黑白片段、20 秒准确取帧、14.2 秒仅邻近回退、16 秒整段黑场拒绝替换、取消后释放解码器。结果写入 `artifacts/preview-quality-051.json` 及对应 JPEG。
