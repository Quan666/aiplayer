# 局域网投屏

本版实现 DLNA / UPnP AVTransport 接收设备的发现和播放控制。播放器投屏按钮打开设备列表，用户明确选中设备后才连接视频来源。可填写设备的 HTTP 描述地址作为发现失败时的入口。没有实现 Chromecast 协议或系统 AirPlay 路由选择，不应把 DLNA 按钮描述为这两种协议的支持。

客户端读取视频并通过临时 HTTP Range 桥接发给选中的设备，服务端同步组件不参与。桥接仅绑定通向所选设备的本机网络接口，允许所选设备 IP 和随机 32 字节会话令牌对应的单个文件地址。它不提供目录列表，也不把 SMB/WebDAV/HTTP 原视频地址、源账号或密码发给电视。停止投屏、退出播放器或取消连接时关闭桥接；旧地址随之失效。

控制包括播放、暂停、相对时间定位、播放时间轮询和接收设备支持时的音量控制。设备的实际时间用于记录续播，不合并不同集数的进度。源不支持 Range 时拒绝非零偏移并提示；读取断网等失败会保留播放器并显示可排查的错误。设备自身不支持的格式、解码器或 Seek 操作也会显示错误。

不转码：视频容器、视频编码、音轨和内嵌字幕是否能播放取决于接收设备。手机端 libass 样式、弹幕、繁简转换、AI 翻译结果和播放器界面不会合成到投屏视频。外挂字幕没有自动提供给 DLNA 接收设备。加密/需认证的来源仍由客户端读取，不能保证设备支持其容器与编码。

连接取消使用启动/停止屏障：先取消正在进行的控制请求，等待启动流程退出，再用独立限时连接发送最终 Stop；迟到的来源连接或桥接会自行关闭。保存记录异常不应阻断网络清理。停止后恢复本机播放须确认播放器实际位置已到达远端记录位置；仅 seek 调用返回不算恢复成功。恢复失败时保持暂停和远端记录，并提示重新打开视频续播，避免以旧的本机位置覆盖新进度。

已完成受控回环测试：SOAP 参数与中文 XML、随机访问/HEAD、错误码、所选 IP/令牌隔离、迟到连接释放、SetURI 取消后没有迟到 Play、最终 Stop、源读取/Range 错误反馈，以及实际位置恢复确认。尚未用真实物理电视验收兼容性。

`scripts/dlna_fixture.py` 提供可复现的接收设备测试驱动。Android 模拟器需先执行 `adb reverse tcp:1446 tcp:1446`，然后运行脚本并传入 `--adb`、`--serial` 和 `--report`。应用内手动添加 `http://127.0.0.1:1446/description.xml`。驱动对动态视频桥接做 HEAD 和首段/中段 Range 读取，可用 `--fixture` 比较首段哈希；它只模拟接收端控制，不渲染视频或转码，因此测试通过不等同于物理电视播放验收。

0.5.0 最终 Linux 发布包已完成实际 UI → 接收器控制 → 单文件视频读取 → 停止 / 本机恢复的自动验收，见 [历史验证记录](VALIDATION.md)；原始报告已随过时产物清理。每个 SOAP 消息显式设置 UTF-8 字节数的 Content-Length；测试接收器也支持有界 chunked 读取。协议格式依据 [UPnP Device Architecture](https://upnp.org/specs/arch/UPnP-arch-DeviceArchitecture-v2.0-20140901.pdf)。
