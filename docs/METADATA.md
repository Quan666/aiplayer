# 作品识别与观看记录

普通资料检索固定联合查询 Bangumi 动画、TMDB 剧集和 TMDB 电影，不再选择单一资料来源。自动识别默认使用严格策略；TMDB 需要在「设置 → 常规 → 作品资料」填写 API Key 或读取令牌，未配置时 Bangumi 仍可使用。凭证保存在设备安全存储的 `tmdb.apiKey`，不以明文进入 SQLite 设置或日志；0.5.3 起启用设备同步后，凭据随配置加密同步。API Key（v3）按官方规定通过 `api_key` 参数发送，API Read Access Token 通过 `Authorization: Bearer` 请求头发送；HTTP 客户端不跟随重定向，错误不包含请求地址。

普通识别仅查询本地清理后的作品名称、季度和服务返回的数字资料编号，资料接口使用 GET。输入为路径、URL 或含控制字符时不发出资料查询。可选 AI 识别只接收去除路径的文件名，以及真实候选的名称、别名、年份、类型、季度和资料编号；视频内容、文件哈希、截图、源文件完整路径、源凭证和视频直链均不会上传。AI 识别复用「设置 → AI 翻译」的服务与模型，使用独立识别请求和缓存，不受字幕翻译提示词或目标语言影响。

- **关闭**：不自动请求联网资料；保留已有海报、已确认的同系列资料和手动匹配入口。
- **严格**：只有作品名称、季度和类型吻合且候选唯一时采用。两源确定为同一动画时优先 Bangumi；没有可信 Bangumi 结果时采用唯一 TMDB 电影或剧集。两源的作品、年份或类型冲突时不强配。TMDB 的指定季度须实际存在后才接受季度海报。
- **扩展**：在严格策略基础上，允许至少 5 字符、长度差小于约 15% 的唯一近似前后缀名称；季度约束仍生效。存在歧义时不猜测。

本地已确认身份只在同名、同季度且资料编号唯一的组内补齐。人工更正不被扫描或自动匹配覆盖。元数据、弹幕匹配和观看记录分别保存。海报与小标题只有确定作品身份后才跨单集共享；不同季度不会自动共用海报。

继续观看和观看历史每个系列/季度仅显示最近观看的一集；未识别的非分集视频独立显示。排序按最后播放时间。每集、每个视频版本的精确进度保持独立，因此返回旧一集仍从那一集原来的位置继续。详情中的播放列表显示每集进度及最近观看时间，继续观看按钮指向该系列最新播放的一集。

退出播放器时立即返回，随后复用当前解码器截取暂停位置的画面并更新封面。解码器清理和封面保存不阻塞返回手势。图片文件名随帧版本变化，避免图像缓存继续显示旧封面；异步返回的旧位置截图被丢弃。失败时保留原封面，后台生成队列优先处理已有观看进度的视频。

官方协议依据：

- [TMDB 应用认证](https://developer.themoviedb.org/docs/authentication-application)
- [TMDB 电视剧搜索](https://developer.themoviedb.org/reference/search-tv)
- [TMDB 电视剧详情](https://developer.themoviedb.org/reference/tv-series-details)
- [TMDB 季度详情](https://developer.themoviedb.org/reference/tv-season-details)
- [TMDB 署名要求](https://developer.themoviedb.org/docs/faq)
- [Bangumi API](https://bangumi.github.io/api/)

本轮协议测试使用受控响应验证隐私、身份歧义、季度和凭证行为；尚未使用用户的 TMDB 凭证验证在线结果。

## 来源与影视库统一展示

来源目录和影视库详情共用作品标题、海报、评分、季度、简介及集数统计。作品的总集数来自资料服务，已收录集数按季度/集号去重；同集的不同编码或多个来源的副本保留为可播放文件，但不重复计算集数。目录识别成功后同步各集记录，旧影视库详情先展示已有资料，再后台补齐可访问目录中的未播放剧集。不同作品身份和人工更正受到保护；从库移除但保留源文件的条目不会因自动补全重新加入，显式导入或播放仍可重新收录。

来源中的文件夹、远程视频和本地视频支持长按「重新识别影视资料」或「手动搜索匹配」。主动识别可在关闭自动识别时使用；没有唯一结果时提供输入作品名的搜索入口。文件夹匹配范围仅包含选中目录的视频。

单个视频也保留并显示识别到的季度、集数和单集标题。默认第 1 季在没有多季资料时省略；已确认作品有多季时保留第 1 季，第 2 季及以上始终显示，季度 0 显示为特别篇。这里只调整展示，不删除季集数据，也不改变各视频的播放进度。

视频规格与作品资料分开保存。播放后从解码器读取实际封装、视频编码、宽高和可用的视频码率，缓存后在详情中展示；文件大小来自文件或来源目录。未取得实际宽高时，文件名中的 1080p、2160p 等仅显示为「文件名标注」，不会当作实测规格。拿不到的编码或码率保持空缺；不同文件版本分别缓存，文件位置、大小或修改时间变化后失效，技术信息不参与同步。

简介提供展开、AI 翻译、取消和原文切换，共用「设置 → AI 翻译」中的服务、模型与目标语言。点击翻译后直接调用已配置的服务；翻译缓存只存本机，按原文与翻译配置隔离。此功能不参与文件名的自动资料识别。

「AI 翻译简介」右侧的「AI 翻译标题」可批量翻译作品名和已取得的单集标题，点击后直接翻译。只有标题文字及目标语言会发送；数字季度、集数保持本地生成。译文完整校验后作为本机显示缓存应用，影视库、来源详情、播放列表和播放标题共享，支持切回原文；不改原文件名、匹配身份或同步元数据。更换服务、模型、语言或原文后使用对应缓存。

## 联合检索与多语言译名

“匹配影视资料”使用可随键盘调整的滚动面板，始终联合搜索两源，结果标明 Bangumi 或 TMDB，TMDB 结果同时区分电影和剧集。季度可直接修正，特别篇使用 0，电影无需季度。TMDB 凭证在设置中填写，未填写时 Bangumi 搜索仍可使用；某个来源暂时失败时，仍保留其他来源返回的候选。配置后可点击“识别未匹配的视频”对现有未识别条目执行当前策略；关闭自动识别时该按钮禁用。修正资料和季度不改变每个视频版本已保存的播放进度。

TMDB 官方多语言译名辅助已内建到联合检索中，不再提供独立开关。对唯一 TMDB 身份读取 `alternative_titles` 和 `translations`，将收录的中文、日文原名、英文译名等回用于 Bangumi 搜索；回查结果仍须独立通过名称、季度及跨源身份校验。最终资料始终携带对应的来源、类型和编号，不把 TMDB 编号误作 Bangumi 编号，也不会自动覆盖用户已确认的资料。

这里使用 TMDB 收录的跨语言作品名称和别名，并非对任意文件名做机器翻译。TMDB 搜索只返回当前语言标题与原始标题，因此自动识别会用详情的 `append_to_response=alternative_titles,translations` 核对英文别名、罗马字名称及其他已收录译名。中文资料优先使用 `zh-CN`，没有时回退至 TMDB 的其他中文地区译名。用于 Bangumi 的查询数有上限，优先中文名、原名和英文译名；全部别名仍参与 TMDB 身份校验。两个不同作品拥有相同别名、查询结果超过一页、指定季度不存在或候选详情读取失败时，不自动猜选。可以改用手动搜索和选取。

普通检索仍只发送整理后的作品名、季度和服务返回的数字编号。多语言译名缓存只包含公开资料，不存储 API Key。旧版本的单源偏好和译名辅助开关不再限制联合搜索，旧匹配缓存会被新版本缓存隔离。0.5.3 起远程视频位置与匹配结果可通过设备同步恢复；媒体文件、本机文件路径、翻译缓存和截图不上传。关闭自动识别后不再自动发起资料请求，手动搜索仍可使用。

新增官方协议依据：

- [TMDB 电视剧别名](https://developer.themoviedb.org/reference/tv-series-alternative-titles)
- [TMDB 电视剧翻译条目](https://developer.themoviedb.org/reference/tv-series-translations)
- [TMDB 合并详情子请求](https://developer.themoviedb.org/docs/append-to-response)
- [TMDB 搜索与详情流程](https://developer.themoviedb.org/docs/search-and-query-for-details)

## 可选 AI 识别回退

「设置 → 常规 → 作品资料 → AI 自动识别信息」默认关闭。启用并配置 AI 服务、模型后，普通联合识别未匹配到作品时，AI 会从文件名提取作品名称、已知译名、类型和季集，再联合搜索真实资料，最后核对候选与详情。AI 只能选择实际返回的候选，不能提供虚构编号、海报或简介；低置信度、类型或季度不符、仍有歧义时保留未匹配状态。

来源目录同样支持此回退，包括单视频目录和普通规则无法解析的文件名。多个视频必须全部确认到相同的来源、作品、类型和季度才组成作品目录；混合目录继续按文件浏览。关闭自动识别、取消操作或更换识别配置后，迟到的自动结果不应用到界面或目录缓存。

手动匹配弹窗中的「AI 自动识别」可直接触发解析与候选核对，不要求打开自动回退开关。批量处理会分别解析每个文件，保留各自集号；无法唯一确认时展示真实搜索结果，供人工选择。人工选定结果只更改选中范围的影视资料，不改变文件位置或观看进度。

## 批量识别与后台任务

文件名分析每批最多 20 个尚未缓存的文件，最多并行 2 个 AI 分析请求。解析后按作品和季度分组，同组共享资料搜索、详情及候选确认，保留每个文件自己的季集；资料查询最多同时处理 3 个作品组。同一资料编号的详情、季度及集名请求会合并，取消一个调用不会打断仍在等待的其他调用。

识别任务由应用管理，面板显示已处理、已匹配和失败数。关闭面板、点击「后台识别」或切换页面后任务继续，可通过任务按钮重新查看；点击「取消任务」才取消该任务。已完成结果立即保存，尚未完成的文件和任务选择在本机保存，重启后会恢复仍然适用的工作。后台处理指应用进程仍在运行时继续执行，不保证操作系统挂起或强杀后仍能联网；重新打开后从保存的进度恢复。

## 长期保存与失效条件

成功的识别结果、完整搜索结果、官方详情、季度详情、集名和目录资料长期保存在本机，重启后直接复用，不按时间或条目数量自动过期、删除。字幕、标题和简介翻译继续按原文与 AI 配置保存；成功弹幕缓存同样长期保留，播放中的主动刷新仍可更新内容。普通重新识别会复用已有成功数据，明确刷新可更新对应资料。

联网失败、空搜索、空集名和未确认作品的目录结果不会成为永久的未匹配缓存，稍后仍可重试。仅部分来源成功的搜索也不会遮住恢复后的其他来源；添加或更换 TMDB 凭证后使用对应的搜索缓存。凭证只以摘要参与资料缓存标识，不写入公开资料缓存正文。

长期保存不取消身份校验：目录内容指纹、来源配置、文件位置或版本、识别策略和 AI 配置变化时，不适用的结果仍会失效；人工更正和取消后的迟到结果保护保持不变。用户主动删除或清理、系统清除应用数据及卸载不属于自动缓存淘汰。

## 海报缓存

作品海报首次下载后以 URL 摘要作为文件名保存在本机 `poster-cache-v1` 目录。影视库、来源文件夹、收藏和详情共用同一缓存；成功图片长期保存，重建界面、重启或离线时直接读取，不因总容量或长时间未访问而自动删除。并发同 URL 合并，最多同时下载 4 张，单张最多 12MB、超时 15 秒；图片校验通过后原子写盘。失效或不支持的图片回退本机视频帧或占位图，短暂退避避免重复请求，缓存不参与同步。

长期磁盘缓存与播放器内存资源分别管理。拖动预览的临时解码帧、解码器和来源连接仍会在结束拖动、空闲或退出时按生命周期释放；这些资源不是需要跨重启保存的资料和海报缓存。
