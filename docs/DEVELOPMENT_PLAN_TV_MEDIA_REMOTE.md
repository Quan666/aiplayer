## 1. 目标与范围

在现有播放器基础上，为 Android、iOS/iPadOS、Windows、macOS 及现有 Linux 客户端增加图片、RAW 图片和音乐支持，并增加适合 NAS 照片与自拍视频混放目录的相册浏览模式；为 Android 电视增加专用布局、完整遥控器操作和手机扫码输入、控制。增加默认关闭的自动识别开关，只有启用后，进入文件夹才后台自动识别。

各端复用媒体分类、来源访问、索引、缓存、解码调度和播放能力，分别适配触屏、键鼠及电视遥控器。采用统一、紧凑、有序的界面风格，避免不必要的副标题、说明和装饰。

| 需求 | 适用范围 | 交付目标 |
| --- | --- | --- |
| 图片浏览 | 全部现有客户端 | 文件浏览、缩略图、全屏、切图、旋转、缩放和幻灯片 |
| 相册浏览模式 | 全部现有客户端，重点适配 NAS 与电视 | 四列细白间隔照片墙、照片/RAW/自拍视频混排，同名多文件分组、动态类型筛选、统一查看与返回 |
| 文件夹预览与布局 | 全部现有客户端 | 文件夹图片封面、四列网格与内部细间隔，支持触屏、键鼠和遥控器 |
| 多格式及 RAW | 全部现有客户端 | 明确格式矩阵，优先内嵌预览，按需完整解码并缓存 |
| 音乐 | 全部现有客户端 | 文件播放、基础音乐库、标签和封面、队列、播放控制 |
| 电视模式 | Android 电视 | 适合远距离观看的布局与完整遥控器操作 |
| 手机扫码输入、控制 | Android 电视接收控制，手机浏览器操作 | 局域网配对、文字输入、导航、媒体控制及状态反馈 |
| 自动识别开关 | 全部现有客户端，含电视模式 | 默认关闭，进入文件夹后按条件后台执行，手动识别独立可用 |

## 2. 实施前基础与改造点

- 项目已有 Flutter 多端工程、`media_kit` 播放内核、媒体按键及键盘处理；Android 当前最低版本为 API 24（Android 7.0）。
- 来源浏览、导入、资料识别和影视库主要围绕视频设计。扩展时须引入明确的媒体类型，检查所有视频专用入口，避免只添加文件后缀就将图片、音乐送入影视识别或剧集逻辑。
- 已有海报、封面缓存和后台 worker，可评估复用；图片原图、RAW 预览和音乐封面应有各自的缓存身份、尺寸和失效规则。
- `client/lib/cast/bridge.dart` 已有局域网临时 HTTP 服务，可参考接口选择、会话和清理方式；手机配对、控制协议和网页需要新增。现有 DLNA 投屏与手机控制分别管理连接和生命周期。
- 现有 `metadataStrategy` 为 `off / conservative / balanced`，默认 `conservative`；`aiMetadataEnabled` 默认关闭。目录、导入、待识别队列及恢复路径须统一检查新开关。
- 现有 Go 服务负责资料同步。首版局域网手机控制由电视客户端提供，无需部署同步服务。

相关现状文档：[作品识别](METADATA.md)、[图片与视频预览](PREVIEWS.md)、[局域网投屏](CASTING.md)、[验证记录](VALIDATION.md)。需求与当前实现须按第 14 节区分。

## 3. 全端媒体模型与来源

- 视频、图片、音乐分别分类；混合目录可按类型筛选，保留原有视频功能和文件浏览入口。
- 复用本地、HTTP、WebDAV、SMB 等现有来源，按协议实际能力处理鉴权、范围读取、随机访问和取消。需要完整文件的解码器使用有上限的临时磁盘缓存，不将大文件完整搬入 UI 内存。
- 从来源浏览、导入、外部打开、搜索、排序、详情到离线下载，逐项标明各类媒体的支持范围；视频专用操作不出现在图片、音乐上。
- 为媒体身份、类型、文件修订、技术信息及用户状态设计兼容迁移；保留现有影视资料、人工匹配、收藏、进度和来源配置。
- 资料同步按媒体类型扩展并定义旧客户端兼容行为；原始照片、RAW、音乐文件不因资料同步而自动上传。

## 4. 图片与 RAW

### 4.1 浏览能力

- 相册或文件网格惰性加载缩略图，支持全屏、前后切图、旋转、缩放和平移。
- 正确应用图片方向信息，定义色彩配置和高位深图片的显示转换策略；色彩准确性需单独验证。
- 幻灯片仅在用户启动且页面可见时运行；退出或后台立即停止，恢复前台不擅自重启。
- 超大图按显示尺寸生成预览，进一步放大时按需读取更高分辨率或分块；限制同时保留的解码图与 GPU 纹理。

### 4.2 格式支持

| 格式组 | 计划 | 验收要求 |
| --- | --- | --- |
| JPEG、PNG、WebP、GIF、BMP | 首批普通图片支持 | 各端用真实文件验证；GIF/WebP 动画明确静态预览与播放行为 |
| TIFF、HEIC/HEIF、AVIF 等 | 扩展格式适配 | 按平台、编码变体及实际解码器列出支持范围，不能只依赖系统版本判断 |
| CR2、CR3、NEF、ARW、RAF、ORF、RW2、DNG 等 RAW | 评估 LibRaw 等原生解码方案 | 按相机型号、压缩变体、内嵌预览及完整解码分别记录 |

“支持 RAW”需区分内嵌预览与原始数据完整解码，界面在用户需要判断画质时给出简短状态。不能根据扩展名宣称支持全部相机，不能将小缩略图放大后当作完整解码结果。

### 4.3 弱电视处理策略

1. 优先提取合适的内嵌预览，生成列表和屏幕尺寸缓存；预览不存在或分辨率不足时走受控回退。
2. 按需在后台 worker 或平台工作线程完整解码。弱电视默认单个重型图片任务在途，等待队列有界，当前图优先，快速切图丢弃过期请求。
3. 完整解码前检查像素、预计内存、文件大小和剩余缓存预算；超限或不支持时给出可重试的明确结果，不循环重试或崩溃。
4. 无法中断的原生解码仅允许有界在途任务结束；取消后不发布旧结果、不继续补槽。
5. 记录解码器版本、文件修订、预览来源、输出尺寸、方向及色彩转换版本，确保缓存正确失效。

6000×4000 图片的一份 8 位 RGBA 像素约为 96 MB，完整解码还可能需要中间缓冲和 GPU 纹理。后台执行只能避免阻塞交互，仍须限制总内存和原生工作线程数量。

可选后续能力：在 NAS/电脑生成屏幕尺寸预览，供弱电视读取。它不是首版使用图片功能的前置条件，需要另行设计服务和缓存协议。

### 4.4 相册模式入口与范围

用户场景：NAS 的同一个文件夹中同时保存照片、RAW、手机或相机自拍视频，希望按同一次旅行、活动或家庭记录连续浏览，无需将视频移到其他目录。

- 当前通过目录工具栏切换到相册，相册工具栏及更多菜单提供“文件视图”，切回当前文件夹并保存显示方式；沉浸浏览显示工具栏后也可切回。文件视图点击图片只打开查看器，返回后仍保留文件视图。后续“设为相册”和常用入口另行扩展，无需复制、移动文件或导入影视库。
- 该显示能力适用于所有现有客户端；复用来源身份、目录路径和文件修订，首版按设备记住模式、排序、筛选与滚动位置。
- “设为相册”作为明确的内容用途选择，对其子目录默认继承；子目录可显式覆盖，使用最近祖先的有效设置。仅为当前页面切换相册视图时，该目录当前浏览会话同样按个人媒体处理。
- 初始使用不根据文件比例或后台扫描自动改成相册。用户设置后直接进入已选模式，必要控制收在工具栏或菜单，避免逐卡添加说明。
- 默认展示当前文件夹的照片、RAW、视频和子文件夹；明确选择其他类型或“全部”后，也可展示音乐和普通文件。子文件夹可独立进入，不自动递归展开或计算全树媒体数量。
- “包含子文件夹的时间线”列为后续可选能力，须用户明确启动有范围、进度、暂停和取消的索引任务；不能让进入目录变成全 NAS 扫描。

### 4.5 相册页面布局

```text
旅行 / 海边                        筛选   ⋯
┌────────┬────────┬────────┬────────┐
│  照片  │  照片  │▶ 00:32│  照片  │
├────────┼────────┼────────┼────────┤
│  照片  │ 照片组 │  照片  │  照片  │
├────────┼────────┼────────┼────────┤
│  照片  │▶ 01:08│  照片  │  照片  │
└────────┴────────┴────────┴────────┘
```

线框只表示相邻单元格的位置，实际界面保留内部 1.5px 细白间隔，不显示“照片”等占位文字。

- 全端采用类似手机相册的四列照片墙：内部横纵间隔为 1.5px 白色，两侧没有外边距；不使用圆角、阴影或常驻文字区。缩略图等比填充裁切，完整画面在查看器中显示。
- 顶部保留简洁路径、文件视图切换、筛选及更多操作，排序放在筛选底部面板中，不再提供尺寸切换。默认显示照片、RAW、视频和文件夹；音乐、文档及伴随文件可从动态类型中明确选择，也可继续使用文件视图。
- 支持沉浸浏览，隐藏应用侧栏、工具栏等外围界面，让照片墙占满可用屏幕；点击、鼠标操作或遥控器菜单操作可唤出控制。图像延伸到顶部状态栏、底部系统栏与浮动导航栏下方，仅交互控件使用安全区域并保留返回路径，电视不把交互控件放入可能被裁切的边缘。
- 使用固定单元格、可预测列数的惰性网格，默认方形裁切；不采用高度不断变化的瀑布流。适配窗口及横竖屏，保持默认四列，网格末列覆盖取整余量，避免出现像素缝。
- 视频仅显示播放标记和已知时长；照片组可使用一个小叠层/数量标记，必要时显示 RAW 状态。文件名、全部后缀和规格在查看器或详情中展示，不逐格堆叠。
- 文件夹使用图片封面并保留简短名称，在墙首部沿用四列与内部细白间隔；是否显示由“文件夹”类型控制。文件夹预览与封面规则见第 4.12 节。
- 默认连续铺墙。后续日期浮层、定位入口与按日分段视图须单独实现；分段视图可在日期之间增加标题，组内仍保持四列与细白间隔。当前不显示尚未实现的日期分段控件。
- 电视焦点用格内描边或轻量遮罩表示，不另加焦点间隙，不以放大挤压相邻项。手机触屏、桌面键鼠和电视遥控共享内容及筛选语义。

### 4.6 时间、排序与本地索引

- 当前默认按名称浏览，提供名称、修改时间、已知拍摄时间、大小和类型排序，按目录保存。后续完整时间线目标为按拍摄时间讲述活动过程；时区解释与视频时间索引完成前，不将当前顺序称为完整时间线。
- 照片优先使用 EXIF 原始拍摄时间及其偏移信息；视频优先使用可信的拍摄/内容创建时间。没有可靠拍摄时间时，回退到文件修改时间，再以稳定文件身份和名称保证顺序；缺少时间不编造日期。
- 拍摄时间、文件修改时间和首次发现时间分别保存，详情可查看时间来源。NAS 复制或迁移改变修改时间时，不覆盖已读取的有效拍摄时间。
- 保存时间原值、偏移是否已知、采用的解释规则和解析版本。视频时间可能存在 UTC 与设备本地时间写入差异，未知时区不强行转换；同一规则变更统一重建相应时间索引。
- 目录列表当前只有 `SourceEntry.modified` 等基础属性，不能将它直接当作拍摄时间。新增 EXIF/视频元数据后台提取与独立连接索引，目录项复用批量快照，禁止逐卡探测。
- 首屏优先展示现有索引和可用目录信息。日期未就绪项位于稳定的待索引区，按日分段视图中归入“时间待读取”；默认照片墙不为此插入额外标题。本轮后台补全先合并快照，在安全时机刷新，正在滚动、按键导航或查看媒体时不重排当前序列。
- 日期排序未完整时不能把临时顺序称为完整时间线。首次为超大目录建立时间索引可显示单个进度入口并允许暂停，媒体仍可按文件名浏览；返回后焦点按媒体身份恢复。
- 文件扫描、日期提取、排序和日期聚合在后台进行并批量提交；无修订变化不重复读取，失败按文件修订退避。支持协议的范围读取，必要整文件缓存有大小上限和超时。

### 4.7 统一查看器与电视交互

- 图片、视频和明确选入的音乐遵循当前筛选与排序；查看器前后导航使用后台预备的媒体邻项映射，跳过文件夹及普通文件，不在 UI 中扫描目录。普通文件独立显示并提供下载操作，不送入图片解码器或播放器。
- 同名多格式照片组只占一个主序列位置，查看器提供组内文件选择，显示各自后缀、尺寸及可用状态；主序列前后切换不会把同一照片的全部格式重复播放。展开为文件浏览后则按匹配文件逐项查看。
- 查看模式下左右切换媒体；视频播放时左右优先服务播放器焦点或定位，前后媒体使用明确按钮/媒体键，避免按键既切图又定位。手机扫码页面提供前后项和播放控制。
- 手机横向单指滑动切换媒体，放大或多指缩放期间不切项；单击切换白/黑画布，默认和初次加载使用白色，用户选定的背景在切图时保留。双击围绕点击位置放大或还原。
- 顶部保留返回、组内格式、信息及更多操作；信息使用紧凑底部面板，只展示已知文件名、类型、原图尺寸、拍摄/修改日期、大小及来源位置。旋转、缩放、幻灯片和背景切换收进更多菜单，保留遥控器可达路径。
- 图片及背景铺到屏幕边缘，只有控件使用安全区域。放大图片后方向键用于平移；返回先还原缩放，再退出查看器。信息或菜单打开时先关闭当前层；退出查看器前完成系统栏恢复，避免迟到恢复覆盖后续播放器状态。
- 返回网格恢复打开查看器前的精确像素滚动位置及原媒体焦点，不按查看器最后一张或网格行首重新定位。源文件删除或筛选变化时选择合理邻项，不因索引更新丢失当前媒体身份。
- 视频卡片和焦点停留不自动播放或连续播放预览；静态封面在可见、停止滚动后按需交给共用有界队列生成。时长未知时不编造数值，目录级时长展示随后续索引完善。
- 幻灯片由用户显式启动，默认仅播放照片；可选包含视频，默认停在视频封面等待播放。自动播放视频及其声音须有明确选项，不能因进入目录或恢复前台突然发声。
- 视频播放时暂停相册的缩图、RAW 完整解码及可推迟的元数据补全，避免与实际播放争用 CPU、内存及网络。

### 4.8 个人媒体与影视识别隔离

- 有效相册目录及当前相册浏览会话中的自拍视频视为个人媒体，即使打开全局自动识别，也不自动向 Bangumi、TMDB 或 AI 提交名称，不生成作品/季度/剧集分组。
- 保存相册目录用途时取消该目录及继承范围内的自动影视任务、待处理队列，提交前校验用途修订；移回文件模式也不能使旧队列复活，只按当前明确设置和新事件重新判断。
- 现有影视资料与人工匹配不因切换显示模式被删除；个人媒体播放历史与影视续集队列隔离，保留必要位置且不挤入作品季集分组。
- EXIF、视频时间、时长和缩略图是本地媒体读取能力，不受联网自动识别开关控制；仍遵守后台、播放期、滚动和任务预算。
- 首版浏览不改原文件及 EXIF、不写入 NAS、不主动删除文件；删除、移动、写回标签等功能需要另行定义操作和撤销语义。
- 同名多格式、多文件照片分组为相册必需能力，按第 4.10 节实施，不能限为 RAW+JPEG 两文件配对。Live Photo/动态照片需另行确定格式支持范围，不能将同名普通视频直接当作照片附属文件。

### 4.9 NAS 与弱电视专项策略

- 优先读取本机已有缩略图和可用内嵌预览，仅生成视口附近的小量图片；相邻全屏预取有界，快速滚动取消或合并旧请求，结束后按需恢复。
- NAS 返回的是原文件时不默认下载全部原图，不同时为照片、RAW、视频开多条无界解码管线。弱电视共用重型预览预算，首版默认单个任务在途，按真机测量调整。
- 视频封面首次按需用受控解码器提取并缓存，不为所有视频同时打开播放器；封面失败保留可点击的播放图标，有退避且可手动重试。
- 缓存键包含来源、文件身份/路径、大小、修改或协议修订、缩略图尺寸和生成器版本；无可靠文件修订时明确失效和刷新策略，不无限信任旧图。
- NAS 断连显示可用缓存，保留目录状态并提供重试；恢复连接后批量核对变化，不能以持续轮询保持 NAS 或电视唤醒。
- 不依赖 NAS 品牌私有缩略图路径或必须安装特定相册套件。NAS 侧共享缩图服务为可选后续方案，须有正式接口及失效规则。

### 4.10 同名多格式、多文件照片组（全端必需）

- 典型例子：同一目录的 `001.jpg`、`001.jpeg`、`001.arw`、`001.dng`、`001.tif` 归为一个照片组；支持不同后缀、多个普通图片版本、多个 RAW 版本，不设置两成员限制，不能在模型中写死一对一 JPG/RAW 字段。
- 分组以“来源身份 + 父目录身份 + 去除已识别图片后缀后的完整文件名”为默认键；只移除末尾的格式后缀，不删除编号、编辑标记或其他词。`001.edited.jpg` 不自动并入 `001.jpg`，不同目录的 `001` 不跨目录合并。
- 后缀匹配忽略大小写，`.jpg / .jpeg / .JPG` 等通过可扩展的格式注册表识别。文件名主体遵循来源的大小写及 Unicode 语义；来源允许 `A` 与 `a` 共存时不强行合并，无法确定时保守保留各文件。
- 分组条件是同名候选，不能宣称它们像素相同。默认合并展示，用户可关闭“合并同名照片”、展开组内文件或手动拆分/恢复分组；这些操作只影响浏览，不改名、不移动、不删除原文件。
- 照片组保存独立组身份及一对多成员，成员各自保留格式、路径、文件修订、元数据、解码结果和失败状态。文件增删、换后缀、改名、人工拆分及目录迁移均有一致性与重新分组规则；一个成员失败不能使整组消失。
- 预览先采用用户指定且符合当前筛选的成员，否则按明确且稳定的规则选择可解码普通图片，再尝试 RAW 内嵌预览及按需完整解码。文件名相同不代表必须优先下载或完整解码全部成员。
- 分组可收纳格式注册表已识别、当前设备尚不能解码的图片成员，详情明确其不可用状态；可用成员仍可浏览。全端共用分组与候选顺序，平台解码能力不同允许采用下一可用成员。
- 同名 `.mp4 / .mov` 视频继续作为独立媒体项；`.xmp` 等边车文件不计为照片，不并入照片组，默认不显示。明确选择对应类型或“全部”时，边车文件以独立普通文件格展示并可下载，不作为图片解码；未来关联边车元数据须另行定义。
- 组内日期采用已固定主成员的可信拍摄时间，缺失时按稳定候选规则回退，并记录来源；不同成员日期冲突在详情可见。筛选临时换封面不改变组身份或组日期，不让同一照片在时间线上来回跳动。
- 组内文件、人工拆分和封面选择变更须递增修订，增量更新受影响的组、索引和缓存；聚合与筛选在后台 worker 批量执行，成员多时列表惰性构建，不一次读取/解码所有成员。

### 4.11 组合显示筛选（全端必需）

筛选收在统一面板中，默认不占用照片墙空间；显示当前生效状态并支持一键清空。触屏、键鼠和电视遥控器均能完整操作，按目录记住条件，切换视图保留条件。

| 条件 | 语义 |
| --- | --- |
| 类型 | 从当前目录快照提取实际类型，显示“文件夹”“无后缀”和具体后缀标签，例如 JPG、JPEG、ARW、FLAC、TXT、XMP；多选，提供全部和重置，不要求输入后缀 |
| 日期 | 修改或拍摄日期，提供不限、当天、近 7/30 天、自定义范围及未知日期 |
| 排序 | 名称、修改/拍摄时间、文件大小、类型，升序/降序 |
| 显示方式 | 合并同名照片、显示隐藏项；文件夹由类型选择控制 |

移除文件名、文件大小和照片方向输入框；旧条件在面板应用时清理，避免不可见条件继续影响显示。默认相册保留照片、视频和目录；“全部”或明确选择其他类型可显示音乐、文档、伴随文件。大类型列表惰性构建。

- 类型选项由后台从当前目录完整快照生成并排序，不因当前选中类型、日期或其他条件而丢失可选项；隐藏项是否参与由隐藏文件设置决定。JPG、JPEG 等标签只是显示形式，内部仍分别使用精确的 `.jpg`、`.jpeg`，不合并为格式大类。
- 同一条件内多选使用 OR，不同条件使用 AND。以真实文件为单位组合全部条件，再将匹配的图片成员投影到原照片组；必须同一成员同时满足类型和日期等条件，不能由 JPG 满足类型、ARW 满足拍摄日期而错误保留整组。旧配置或其他调用方仍可使用底层包含/排除规则，排除优先；新面板应用时清理这些旧规则，使类型选择准确生效。
- 只筛 `.jpg` 时，仅含 `.arw` 的组不出现；同时有 JPG/ARW 的组只出现一次，预览和默认打开均使用匹配的 JPG，组内浏览默认也只显示匹配成员。详情可明确展示“全部原文件”，但不静默绕过筛选解码/打开被排除的成员。
- 展开为文件后，每个满足条件的文件独立显示；分组/展开或改变条件时按文件/组身份保留可见锚点和合理焦点，计数区分照片组/媒体项与原文件数，不能把 5 个格式误算为 5 张照片。
- 尚未读取的拍摄日期属于未知，日期筛选仅显示已确认匹配项，并区分可读取与暂不支持读取的元数据；按需、可取消地后台补全，不为每次按键重扫 NAS。信息面板同样只显示已知原图尺寸与日期，不能用预览图尺寸或文件修改时间冒充。
- 筛选仅改变显示与优先级，不改原文件、不改变自动识别开关、不发起联网影视识别。条件变更递增查询修订，取消旧缩图/元数据请求，迟到结果不得污染新视图。
- 默认类型包含文件夹；明确类型选择只在包含“文件夹”或“全部”时保留目录，选择单独 JPG 不隐式保留文件夹。目录本身不套用照片日期，封面只使用符合筛选的已知候选，没有可确认候选时显示白色占位。不递归扫描判断目录是否有匹配项；“隐藏无匹配目录”保留为可靠索引完整后的目标。

### 4.12 文件夹预览图与四列布局（全端必需）

- 文件夹支持自动代表图和用户选封面，无可用缓存时显示白色占位；2×2 拼图为后续目标。选封面记录文件身份，后续裁切设置另行定义，不复制原图或写入 NAS。
- 自动代表图从该文件夹已有的受控索引/缓存候选中稳定选择；没有索引时，只对可见文件夹提交低优先级、去重、有总预算与每目录预算的浅层预览任务，不递归探测孙目录，不逐次 build 或 hover 启动任务。单个来源不支持分页时，完整目录响应亦须后台解析并设条目/内存上限，超限保留占位并在进入目录后再处理。
- 文件夹总数、跨层聚合和完整日期不作为预览的前置条件。默认自动封面候选只来自直接子文件，子目录封面另行生成；没有直接媒体时保留文件夹图标，用户可主动选择可访问媒体作为封面。
- 封面与当前筛选、隐藏文件设置和来源权限一致；用户固定的封面不符合条件时使用符合条件的缓存候选或占位，清除筛选后恢复，不自动改掉固定选择。
- 取消大/中/小密度切换，默认四列；只保留内部 1.5px 分隔，两侧不留白。目标解码尺寸按实际单元格与 DPR 计算，缓存尺寸分桶复用。
- 窗口调整或设备旋转保留位置；打开查看器再返回保留精确像素滚动位置、焦点和筛选，不按查看器最后一张照片或行首重新定位。
- 封面选择按设备保存，缓存仍包含目录/成员修订、筛选、目标尺寸和处理版本。滚动中允许读取已缓存小图，有界执行小图解码；原文件请求和重型图片处理延后，屏外预加载不能阻塞可见项。
- 成员删除、封面不可访问、替换原图、权限变更和其他连接提交后更新受影响封面；滚动、后台、播放期及销毁立即停止非必要补槽，返回可见后合并恢复。

设计参考：[Synology Photos 的文件夹与时间线浏览](https://kb.synology.com/en-global/DSM/tutorial/Quick_Start_Synology_Photos)、[视频元数据中的时间与时区差异](https://exiftool.org/TagNames/QuickTime.html)、[LibRaw 的内嵌预览能力](https://github.com/LibRaw/LibRaw)。本节是本项目设计建议，不表示已经具有这些功能或完成兼容验证。

## 5. 音乐

- 复用播放内核，首批目标为 MP3、AAC/M4A、FLAC、WAV、OGG 等常用格式，按实际打包的解码库和样例确认编码、容器组合。
- 支持标题、艺术家、专辑、曲号、时长及内嵌封面；缺少标签时回退到文件名，标签解析、封面提取和批量索引在后台执行。
- 提供文件浏览与基础歌曲、专辑、艺术家视图，支持队列、前后曲、定位、顺序、随机及循环播放。
- 接入既有媒体会话和媒体按键；分别验证移动端锁屏控制、桌面控制及电视遥控器。
- 明确各端后台音频策略。默认后台暂停约束继续适用，只有用户明确启用相应后台播放时保留必要播放资源；进入前台不自动恢复已暂停的播放。
- 记录播放队列和必要状态，避免进度旧写入覆盖新状态；暂停、后台和完成时事件触发最终保存。

歌词、在线曲库、音乐联网刮削和 RAW 编辑不纳入首批基础范围。

## 6. Android 电视模式与实体遥控器

### 6.1 模式及界面

- 复用现有客户端工程，增加电视布局与电视桌面入口、图标及横幅资源；提供电视识别和必要的手动模式选择，兼顾厂商定制安卓电视。
- 核心页面覆盖来源、目录、影视库、图片、音乐、详情、播放器、搜索、设置、任务和所有弹窗。
- 调整远距离可读的字号、焦点和控件尺寸，限制同时展示的重型内容，减少不必要的模糊、阴影、过渡及视频预览。
- 保留视频硬解和用户解码、画质设置。性能策略基于调度、缓存和按需渲染，不擅自降低播放画质。

### 6.2 输入规则

| 输入 | 行为 |
| --- | --- |
| 方向键 | 页面中移动焦点；播放器按当前焦点操作；图片放大时平移 |
| 确定键 | 打开媒体、确认操作、激活当前控件；播放控制按当前场景处理 |
| 返回键 | 先关闭弹窗、菜单或退出缩放，再返回上一级；处理 Android 返回事件 |
| 播放、暂停、快进退、上下曲 | 遥控器提供对应键时映射到当前媒体操作 |
| 长按方向键 | 有界重复导航或定位；不重复打开媒体、弹窗或执行确认动作 |
| 文本输入 | 支持电视系统输入法，并可切换至手机输入 |

- 全部核心流程仅使用方向、确定和返回即可完成，不依赖触摸、鼠标、悬停或长按。
- 焦点高亮统一清晰，自动滚动使焦点可见；返回目录恢复焦点、搜索和滚动位置，原条目消失时选择合理的邻近条目。
- 弹窗进入后接管焦点，关闭后归还触发位置；加载、空列表、错误重试和分页时不丢焦点。
- 输入按页面和控件上下文分发，避免全局播放快捷键抢占列表导航或文本编辑。
- 用目标电视验证实际键值、长按重复、返回键和媒体键差异。

## 7. 手机扫码输入与控制

### 7.1 首版流程

1. 用户在电视中打开“手机控制”，电视选择可达的局域网接口并启动轻量控制服务，显示二维码。
2. 手机扫码，用浏览器打开由电视提供的控制页面，无需安装应用。
3. 使用短时、随机配对凭证完成会话建立；电视显示连接状态并可随时断开。
4. 配对后手机发送操作，电视返回实际执行结果与必要状态；退出控制、会话结束或服务关闭后凭证失效。

手机和电视须局域网互通，电视有线、手机 Wi-Fi 可使用。访客网络、设备隔离、多网卡、网络切换及系统/浏览器局域网权限需要明确反馈和实机测试。

### 7.2 控制能力

- 导航：方向、确定、返回，与实体遥控器共用操作分发逻辑。
- 输入：在手机完成中文等输入法组合，传递已提交文本或有版本的编辑操作；支持搜索词和来源地址，校验目标输入框、编辑会话、光标及提交状态。
- 视频：播放、暂停、定位、剧集切换及应用内音量；显示当前媒体和播放状态。
- 图片：前后切图、旋转、缩放、平移及幻灯片控制。
- 音乐：播放、暂停、上下曲、进度、队列和播放模式。
- 状态：显示控制结果、失联、重连和电视不可用状态；重复发送不重复开播，过期输入不写入新的页面或输入框。

### 7.3 协议、资源与边界

- 采用 HTTP 提供轻量页面，WebSocket 传递指令和事件；命令及状态有体积、频率、连接数和队列上限，定位及连续平移可合并为最新待处理目标。
- 不传屏幕视频来实现遥控，优先传小量状态；不以高频轮询或持续帧刷新维持连接，必要存活检查低频且有超时。
- 配对凭证与控制会话分离，限定有效期、权限和撤销行为；校验网页来源和命令范围，避免局域网任意网页直接控制电视。
- 控制页面不接收已有来源密码、同步 Token 或媒体直链。敏感凭据输入如需支持，应另行评估传输保护，不能直接沿用普通局域网 HTTP 文本输入。
- 网络服务和重型处理放后台 worker；UI 仅接收有界、经过校验的交互指令及小量状态。
- 未启用时不监听控制端口。退出、模型销毁、网络变化及时清理；后台按既有普通暂停、主动后台播放和 PiP 策略收缩服务，禁止远程迟到指令绕过后台暂停。
- 首版控制范围为本应用；电视系统桌面、其他应用、开关机和系统音量取决于厂商接口，另行评估。
- 公网控制、云中继、跨网络自动发现以及手机原生控制入口为后续候选，不是首版局域网配对的依赖。

## 8. 自动识别开关

### 8.1 目标行为

- 新增明确的“进入文件夹自动识别”开关，**默认关闭，适用于全部客户端及电视模式**。
- 新安装和升级后，未明确启用该开关的设备均保持关闭；旧版严格策略或已配置 AI 服务不等于同意启用。
- 建议该自动触发开关按设备保存，避免在手机启用后通过设置同步默默开启弱电视；同步恢复、资料迁移和模型替换不得绕过本机选择。
- 开启后，仅在进入当前文件夹时，先显示可用文件列表和已有资料，再后台识别当前目录的适用视频；不等待识别完成才允许导航或播放。
- 默认不递归子目录，不因列表构建、滚动、悬停或子文件夹卡片出现而自动识别其内部内容。
- 同一目录和配置修订合并请求，优先复用有效结果；无变化重复进入不重复联网，失败有退避并保留手动重试。
- 开关关闭时，启动、导入、同步、页面恢复、任务恢复、待识别队列及目录刷新均不能另起隐式自动识别；已有有效资料仍可显示。
- 开启开关本身不扫描全库，也不立即补跑历史队列；下一次进入文件夹时按当前身份、文件集合和配置判断。
- 当前目标为现有影视资料自动识别。图片本地 EXIF、音乐本地标签提取属于媒体读取；新增联网识图或音乐刮削须另行定义与授权。
- 相册目录及其有效继承范围、当前相册会话中的自拍视频遵守第 4.8 节，不参与自动影视识别；打开全局开关不能覆盖个人媒体用途。

### 8.2 与现有策略、AI 及手动任务的关系

| 配置或操作 | 目标语义 |
| --- | --- |
| 进入文件夹自动识别 | 决定是否允许自动入队，默认关闭 |
| 匹配策略 | 严格或扩展，控制匹配规则，默认严格；不承担自动触发职责 |
| AI 自动识别回退 | 继续默认关闭；自动任务须同时满足自动开关、AI 开关及服务配置 |
| 手动搜索、重新识别、批量识别 | 自动开关关闭时仍可主动执行，保留范围、并发和取消能力 |
| 手动 AI 识别 | 用户明确发起并配置服务时可使用，不要求启用自动触发或 AI 自动回退 |

迁移时将旧 `metadataStrategy=off` 对应为自动触发关闭，并为手动操作保留明确的匹配策略；其他旧策略只保留匹配规则，不自动打开新开关。更新旧文案和批量按钮禁用条件，避免手动入口被自动开关错误禁用。

### 8.3 取消、恢复和结果一致性

- 自动任务仅在相关页面可见、应用前台且不处于播放期时启动或补槽；此处“后台识别”指后台计算，不代表允许应用退到后台后继续识别。
- 关闭开关、离开目录、切换来源、后台或开始播放时，及时取消在途网络与待处理工作；正常任务暂停保留必要检查点，用户取消和销毁永久结束任务。
- 执行前、关键 `await` 后及提交前检查设备开关、任务令牌、目录身份、来源和识别配置修订，拒绝迟到结果及旧队列复活。
- 前台恢复或退出播放后，仅对仍可见的同一目录合并恢复一次，校验已完成批次和有效结果；不恢复已取消任务，不扫描其他目录。
- 缓存覆盖文件增删、来源变化、识别配置变化、人工修正及其他连接提交；已确认资料、人工修改和已移除条目受到保护。
- 检查点以作品/季等共享身份去重，只保存恢复必要数据；取消或暂停不回滚已有效提交的结果，不重复写整批任务。

## 9. 性能与省电约束

遵守仓库 [AGENTS.md](../AGENTS.md) 的全部要求，重点落实：

- UI isolate 只做交互、界面状态和轻量渲染准备。文件读取、数据库批处理、扫描排序、大 JSON、哈希、缩图、RAW 解码与音乐标签提取在复用的后台 worker 或平台工作线程执行；`async` 不能替代后台执行。
- 数据库后台连接独立，保留事务、冲突、取消及跨连接缓存修订；消息只传必要数据，不捕获整个模型或逐项创建 isolate。
- 所有下载、预览、识别和原生解码具备并发与队列上限、去重、超时、取消和退避；任务结束不能补入已失效工作。
- 界面使用预先准备的快照和惰性列表，缩小通知及重建范围；离屏页面暂停更新、预览和动画，返回时合并刷新并保留状态。
- 图片按显示需求和设备像素比例解码，复用磁盘与解码缓存；滚动、切页及后台暂停非必要工作，空闲或恢复后按需补回。
- 生命周期通知直接停工，不依赖下一次 build、帧后回调或 pump；停止动画前结束滚动活动。
- 默认空闲静默，维护与控制连接不空转。暂停或缓冲时停止周期进度心跳，保留必要缓冲和最终进度保存。
- 播放会话、暂停修订与自动续播队列一致校验，迟到的来源准备、原生开播、媒体事件或手机命令不能误开播；不因单纯 inactive 或失焦暂停播放。
- 尊重主动后台播放和 PiP，保留必要音频焦点、媒体会话、网络缓冲及控制；不可见图片、弹幕、动画及首帧探测仍停止。

| 格式 | 本轮边界 |
| --- | --- |
| JPEG、PNG、WebP、GIF、BMP、TIFF 等 | 接入现有 `image` 解码器，按文件内容判定能否解码。动画只取首帧；实际变体和色彩准确性仍需样例验收。 |
| ARW、CR2/CR3、NEF、RAF、DNG 等 RAW 后缀 | 能分类、分组并尝试提取有界范围内的完整 JPEG 内嵌预览，界面注明“RAW 内嵌预览”。没有可用预览时显示失败，不宣称完整 RAW 解码。 |
| HEIC/HEIF、AVIF、JXL | 能分类、分组和筛选，当前解码器尚不提供对应解码；保留成员并显示不可用状态。 |
| 音频/个人视频 | 沿用各端现有 `media_kit`/原生媒体库，识别后缀不代表所有编码均可播放。 |

- 图片服务每实例一个后台 worker、单个重型在途任务和最多 64 个等待请求；普通图片输入上限 64 MiB、解码像素预算 32 Mi 像素，RAW 最多读取前 64 MiB。超限给出可恢复错误，不在 UI 线程完整解码；这些预算仍须按弱电视实测调整。
- 缩略图按显示尺寸和 DPR 解码，JPEG 支持解码阶段缩放；磁盘缓存默认至多 256 MiB / 1024 文件，身份包括来源、文件修订、尺寸及处理版本。目录刷新、封面修改、重试、模型替换和后台取消覆盖缓存/任务失效。
- 当前相册目录上限 20,000 项；WebDAV 列表同时有字节上限，封面仅浅读有界候选。本地枚举可提前停止；SMB 原生层仍先返回整份目录列表再检查上限，是继续优化项。
- 滚动、离屏和后台暂停非必要图片/索引工作；生命周期直接取消任务及补槽，不依赖后续帧。快速后台再恢复不能使旧点击、旧来源准备或旧远程指令突然开播。
- 视频封面与尺寸信息在同一后台事务提交，重新检查文件身份、修订和播放位置；数据库占用时可取消等待，不占用 UI isolate。来源地址或账户改变时撤销旧捕获并使个人视频浏览封面失效，同路径、大小和修改时间不能复用另一来源的旧画面。
